2 Technical Approach Decision
Why Electron + BrowserView?
MethodDescriptionSuitability
Playwright / Puppeteer (Headless) Browser interaction in background, no visible screen ❌ Unsuitable
User cannot see chat windows
Electron + BrowserView Embeds actual websites inside app windows, visible to user ✅ Optimized
iframe Most AI sites block iframe embedding (X-Frame-Options) ❌ Incompatible

BrowserView is a feature provided by Electron that allows an actual Chrome-based browser window to be embedded inside the app. The user can see the actual Gemini/Claude/ChatGPT screens while the app automatically types and extracts text behind the scenes.

↓
Final revised response complete → Display to user

5 Automation Method per AI Site

The app injects JavaScript into each site to perform input and extraction.

AISiteAutomation Method
Geminigemini.google.comFind input via JS → Insert text → Enter

Core Automation Example (JavaScript)
// Enter text in input field (selectors differ per site) document.querySelector('div[contenteditable]').innerText = "Query text"; // Click send button document.querySelector('button[data-testid="send-button"]').click(); // Detect completion: marked complete when no new text is added for a set time // → Monitor DOM changes with MutationObserver // Extract latest response text document.querySelectorAll('.message')[last].innerText;
6 Technical Challenges and Solutions
ChallengeSolution
Varying DOM structures per AISeparately managed selector config files per site
Selectors breaking on UI updatesExternalized selectors in JSON for easy maintenance without rebuilds
Detecting response completionMutationObserver + stability timer + monitoring loading spinner disappearance
Login requirementsUser performs manual one-time login; sessions are persisted afterwards
Bot detection mitigationApplied human-like typing delays and Chrome-masked identity headers
